# MATLAB 求解接口兼容与 MATPOWER OPF 移植方案

本文记录架构设计与实施计划，不代表待规划的接口已经实现。OPF 公式以本机 MATPOWER 7.1
为参照；MATLAB `fmincon` 的兼容范围以本文明确列出的能力为准。

## 1. 目标与边界

目标是让 MATLAB 数值程序保留原有的函数、矩阵、建模和导数计算思路，经过少量语法调整后，
通过 Sparrowzz 的 `fmincon` 使用平台现有求解器。以通用 AC OPF 作为第一个完整验证应用。

确定的调用关系是：

```text
OPF 脚本 → 平台 fmincon → 平台内部 IPOPT 后端
```

- 保留现有 `fmincon` 的“符号表达式 + 自动微分”模式和调用格式。
- 在同一个 `fmincon` 入口增加“函数回调 + 外部导数”模式。
- OPF 脚本不直接调用 IPOPT，也不要求为每个算例手写一套标量变量名。
- 保留 MATPOWER 的主流程、函数名和公式组织，兼容转换集中在平台接口层。
- 本阶段不移植完整 `mpoption`；提供必要的求解选项，以及少量明确的 OPF 配置。
- MIPS 可以作为后续可选求解器，本阶段不以移植 MIPS 为前提。
- 不承诺复现 MATLAB 的全部算法、所有选项或逐次迭代轨迹。

## 2. 现状与真正的接口差别

当前平台 `fmincon` 读取目标表达式、约束表达式、变量名列表和边界，由现有自动微分生成
梯度与 Hessian，再调用 IPOPT。输入中的数值数组并不等于一组已经登记的优化变量。

例如，当前模型可以按下列方式表达：

```text
f = (`a` - 3)^2 + (`b` - 5)^2;
r = fmincon(min(`f`), [], [], [], [-10, -10], [10, 10],
            [`a`, `b`], [0, 0]);
```

MATLAB 的函数模式则把一个函数交给求解器：

```matlab
function [f, df] = cost(x)
    f = (x(1) - 3)^2 + (x(2) - 5)^2;
    df = [2*(x(1) - 3); 2*(x(2) - 5)];
end

options = optimoptions('fmincon', 'SpecifyObjectiveGradient', true);
[x, fval] = fmincon(@cost, [0; 0], [], [], [], [], ...
                   [-10; -10], [10; 10], [], options);
```

这个例子的解是 `[3; 5]`，目标值为 `0`。求解器每次把新的数值数组 `x` 传给 `cost`，
得到函数值和梯度。数组长度可以在调用前根据数据确定，无需创建 `a0、a1……` 等符号名称。

因此，要补的是 `fmincon` 接收和调用脚本函数的通路，以及相应的导数、形状和结果约定。
“动态生成标量变量名”不是实现通用 OPF 的必要路线。

现有实现的主要位置：

| 位置 | 当前作用 | 需要扩展的方向 |
| --- | --- | --- |
| `eig-aoe/src/solvers/mod.rs` | 注册 `fmincon`，解析表达式模型 | 识别回调模式并规范化输入 |
| `eig-aoe/src/solvers/nlp_with_vm.rs` | 表达式自动微分与 IPOPT 对接 | 抽取可复用的求解器适配逻辑 |
| `eig-expr/src/scipt/vm.rs` | 脚本执行、函数调用 | 安全地从原生求解器调用脚本回调 |
| `eig-expr/src/scipt/gc.rs` | 函数对象、上值等运行时对象 | 保证回调及其捕获数据在求解期间有效 |
| `eig-expr/src/scipt/parse.rs`、`codegen.rs` | 脚本解析与编译 | 核实并补齐函数引用、传参与兼容语法 |

VM 已有函数对象、闭包和多返回值相关基础，但这不表示 MATLAB 的 `@fun`、匿名函数或
原生求解器回调脚本已经完整可用。需要以端到端小例子验证。

## 3. MATLAB fmincon 的兼容目标

目标调用形式：

```matlab
[x, fval, exitflag, output, lambda] = ...
    fmincon(fun, x0, A, b, Aeq, beq, lb, ub, nonlcon, options);
```

以上是待支持的 MATLAB 风格形式，不是当前 `.txt` 已实现的语法。

| 能力 | MATLAB 语义 | 平台规划 |
| --- | --- | --- |
| 决策变量 | `x0` 确定大小和形状 | 先支持向量；扩展到矩阵并恢复原形状 |
| 目标函数 | `fun(x)` 返回标量 | 必须支持 |
| 变量边界 | `lb ≤ x ≤ ub` | 支持空边界、无穷边界及尺寸检查 |
| 线性不等式 | `A*x ≤ b` | 必须支持，保留稀疏矩阵 |
| 线性等式 | `Aeq*x = beq` | 必须支持 |
| 非线性约束 | `c(x) ≤ 0`、`ceq(x) = 0` | 必须支持 |
| 一阶导数 | 目标第二输出、约束第三及第四输出 | 支持用户提供的解析导数 |
| 二阶导数 | 内点法的拉格朗日 Hessian 回调 | 支持用户提供的解析 Hessian |
| 无一阶导数 | 有限差分估计 | 后续补充一般函数兼容路径 |
| Hessian 近似 | 随算法和选项变化 | 提供 IPOPT 支持的近似能力并注明差异 |
| 参数传递 | 命名函数、匿名函数、闭包 | 支持绑定模型数据，避免全局变量 |
| 结果 | 解、目标值、退出状态、过程信息、乘子 | 必须支持主要字段 |
| 运行控制 | 迭代上限、容差、输出回调、用户终止 | 分阶段补齐 |
| 其他接口 | `fmincon(problem)`、额外导数输出等 | 后续扩展 |

MATLAB 还提供多个算法及部分算法下的 Hessian 向量积接口。第一阶段只提供平台 IPOPT
后端能够兑现的能力，不伪装支持 SQP、active-set 或矩阵自由 Hessian 求解。
用户请求未支持的算法或选项时，应明确报告，不静默更换算法。

参考：[fmincon 接口](https://www.mathworks.com/help/optim/ug/fmincon.html)、
[算法与适用范围](https://www.mathworks.com/help/optim/ug/choosing-the-algorithm.html)。

## 4. 总体架构

```text
现有表达式脚本                  MATLAB 风格函数脚本
       │                               │
       └───────── 平台 fmincon ─────────┘
                       │
             参数、形状、选项规范化
                       │
                 统一 NLP 问题
                       │
             函数值与导数计算接口
          ┌────────────┼────────────┐
       表达式 AD    用户导数回调   有限差分（后续）
          └────────────┼────────────┘
                       │
                 IPOPT 适配层
                       │
              统一结果 → 返回格式适配
```

### 4.1 同一个入口，两种输入模式

旧模式继续接受现有表达式和参数顺序。新模式接受可调用对象和 MATLAB 风格参数顺序。
两个模式部分参数个数相同，不能只按参数个数分派，应按首参数的类型、显式模式标记等
无歧义信息区分，并对不匹配输入给出清晰错误。

回调应保存为真正的函数对象及其捕获环境，避免以任意字符串求值代替函数句柄。
实现时可以复用现有函数对象；是否需要新的内部类型，以运行时验证结果为准。

### 4.2 统一 NLP 问题

两种入口都转换为内部问题对象，包含：

- 变量数量、原始形状、初值和上下限。
- 约束数量、上下限、各类约束的行范围与来源。
- 目标值、目标梯度、约束值、Jacobian、拉格朗日 Hessian 的计算入口。
- 稀疏结构、导数来源、求解选项和回调生命周期信息。

内部统一采用：

```text
min f(x)
subject to  g_lower ≤ g(x) ≤ g_upper
            x_lower ≤ x ≤ x_upper
```

MATLAB 风格输入可规范化为：

| 输入 | 内部约束块 | 下限 | 上限 |
| --- | --- | --- | --- |
| `A*x ≤ b` | `A*x` | `-Inf` | `b` |
| `Aeq*x = beq` | `Aeq*x` | `beq` | `beq` |
| `c(x) ≤ 0` | `c(x)` | `-Inf` | `0` |
| `ceq(x) = 0` | `ceq(x)` | `0` | `0` |

记录约束块的位置，返回时据此恢复各类乘子。线性约束的导数直接由矩阵得到，无需差分。

### 4.3 导数来源独立配置

| 来源 | 适用情况 | 行为 |
| --- | --- | --- |
| 自动微分 | 当前已支持的表达式 | 保留现有计算图和求导机制 |
| 用户导数 | MATPOWER 等已经提供导数的程序 | 调用脚本获得梯度、Jacobian 和 Hessian |
| 有限差分 | 只有数值结果的普通函数 | 后续实现，考虑变量尺度与边界 |

目标梯度与约束 Jacobian 可分别指定来源。Hessian 可以使用用户回调、完整覆盖模型的
自动微分结果，或后端支持的拟牛顿近似。不能在缺少某些约束二阶导数时，把剩余部分
冒充完整的精确 Hessian。

解析导数是作者推导公式后写入代码；自动微分按运算规则求导；有限差分通过扰动输入近似
导数。三者不能混称。普通函数返回一个数值，并不会自动把函数内部运算图交给现有 AD。

完整脚本函数的自动微分属于后续编译器能力，不作为首版 MATPOWER 移植的前置条件。
对于明确要求但不可用的导数模式，应报错；若允许自动降级，必须在结果中记录实际来源。

### 4.4 回调契约与矩阵约定

MATLAB 风格回调：

```matlab
[f, df] = objective(x);
[c, ceq, GC, GCeq] = constraints(x);
H = hessian(x, lambda);
```

- `df` 为 `n × 1`。
- MATLAB 的 `GC` 为 `n × m_ineq`，每列对应一个约束梯度；`GCeq` 同理。
- 内部 Jacobian 固定为 `m × n`，每行对应一个约束。
- 适配层负责转置和拼接；现有 OPF 数值函数的 Jacobian 不应无条件改动方向。
- 内部 Hessian 回调概念上接受 `(x, lambda, objective_factor)`，返回
  `objective_factor * Hessian(f) + Σ lambda_i * Hessian(g_i)`。
- MATLAB 风格的二参数 Hessian 回调由适配层转换到后端契约；目标权重不为 1 时，需要
  正确组合目标与约束部分，例如利用零乘子调用分离目标 Hessian，不能忽略权重。
- 正确处理约束排列、乘子符号、对称矩阵三角存储，以及稀疏结构与数值分离。

稀疏结构必须覆盖所有可能非零位置，不能仅以初始点的数值非零项确定。小问题可采用保守
稠密结构，大规模 OPF 应从模型拓扑或显式结构接口获取稳定结构。求解中变量及约束数量固定。

参考：[约束梯度约定](https://www.mathworks.com/help/optim/ug/nonlinear-constraints-with-gradients.html)、
[内点法解析 Hessian](https://www.mathworks.com/help/optim/ug/fmincon-interior-point-algorithm-with-analytic-hessian.html)。

### 4.5 脚本运行时与性能

需要一个受控的“原生代码调用脚本函数”接口，负责参数传入、多返回值、调用栈恢复和错误传播。
求解期间固定回调及其捕获的数据，确保垃圾回收不会释放仍在使用的对象。

同一个 VM 的回调默认串行执行；不在未验证线程安全的情况下并发访问。编译与参数检查在
求解前完成，不在每次迭代重新解析脚本。相同输入点的联合函数值/导数结果可以缓存，但
缓存不能混淆不同乘子、目标权重或模型状态。

Hessian、Jacobian 以稀疏格式传递，避免中间步骤把大规模 OPF 矩阵转换为稠密矩阵。
错误应说明回调名称、预期形状及实际返回值，并终止或按后端约定报告计算失败。

### 4.6 选项与返回值

不复制整个 `mpoption`。先提供小型选项对象，覆盖导数模式、Hessian 回调、迭代上限、
容差和日志；必要时支持 `optimoptions`/`optimset` 常用字段名的转换。
MATLAB 容差与 IPOPT 选项不是全部一一对应，必须明确映射和差异。

新接口返回 `x、fval、exitflag、output、lambda`；后续按需要支持 `grad、hessian` 等输出。
`output` 至少包含实际后端、原始状态、退出消息、迭代次数、实际导数来源与可用的可行性指标。
平台退出状态应根据语义转换，不能把 IPOPT 状态码原样当作 MATLAB 的 `exitflag`。

正常求解失败或达到迭代上限时，保留后端提供的最后迭代点、目标值和失败原因；若失败发生
在模型建立之前，应报告输入错误，不能伪造一组解。旧表达式调用的返回格式保持兼容。

## 5. MATLAB 代码迁移所需的语言能力

函数接口兼容不等于完整 MATLAB 语法兼容。建议分开落实：

1. **运行时语义兼容**：可调用对象、参数绑定、多返回值、结构化数据，以及数值/稀疏矩阵。
2. **脚本语法迁移**：先允许机械改写为现有 `.txt`；后续提供独立 MATLAB 兼容入口或转换器。

重点覆盖 `@fun`、`@(x) fun(x, data)`、`mpc.bus`、`[f, df] = fun(x)`。
对于 `nargin/nargout`，支持常用行为或定义机械转换规则，使导数按请求计算。

MATLAB 的 1 基索引、包含末端的区间、按列线性索引/展开、列向量和矩阵运算语义，需要在
兼容入口统一处理。现有 Sparrowzz `.txt` 的 0 基行索引保持原约定，不全局更换索引规则。
矩阵型 `x0` 在内部展开后，回调及最终结果应按兼容模式恢复原形状和元素顺序。

不以实现完整 MATLAB classdef、所有 cell 行为或全部工具箱为前提。MATPOWER 的模型对象
可以先用结构化数据与辅助函数实现相同的变量分组、约束分组和索引行为。

## 6. OPF 的主流程

保留以下职责划分：

| 函数/层 | 职责 |
| --- | --- |
| `runopf` | 用户入口，取得算例并返回结果 |
| `opf` | 检查数据、内部编号转换、组织建模求解和外部编号恢复 |
| `opf_setup` | 创建变量分组、初值、边界、成本、约束和回调 |
| `opf_execute` | 执行求解流程并管理求解配置 |
| `nlpopf_solver` 或同等适配层 | 把 OPF 模型转换为平台 `fmincon` 输入，解包结果 |
| 平台 `fmincon` | 通用模型接口、导数调度和 IPOPT 调用 |

在极坐标 AC OPF 中：

```text
x = [Va; Vm; Pg; Qg]
nb = 在线母线数
ng = 在线发电机数
n = 2*nb + 2*ng
```

`opf_setup` 在运行时创建长度为 `n` 的数组，并记录各变量块的起止位置；成本或模型扩展
引入辅助变量时相应追加。回调根据索引表拆分 `x`，复用数值成本、约束和导数函数。

基础模型包括参考相角、节点功率平衡、电压范围、发电机有功/无功上下限、支路容量与相角差。
成本先完成多项式，再补分段线性成本的辅助变量与约束；仅有 `totcost` 不能代替完整的
分段线性成本建模。

当前 `ext2int/int2ext` 等函数需要核查其对 OPF 的适用性，特别是离线设备、孤立母线、
发电机重排以及成本行的对应关系，不能仅因函数已经存在便视为完整覆盖。

求解后恢复：

- `bus` 中的 `VM/VA`。
- `gen` 中的 `PG/QG/VG`。
- `branch` 中的 `PF/QF/PT/QT`。
- 目标值、成功状态、退出原因，以及已支持的约束/边界乘子。

乘子回填必须处理单位、标幺值缩放及平方限值约束的转换。与 MATPOWER 比较时检查目标值、
可行性与最优性，不要求不同算法逐元素或逐迭代完全相同。

MIPS 如后续加入，可复用模型和导数计算逻辑，但其迭代、线性求解和结果转换仍需单独移植。

## 7. 实施阶段与验收

| 阶段 | 交付内容 | 验收要点 |
| --- | --- | --- |
| 1. 回调闭环 | 现有 `fmincon` 新增函数模式，使用解析导数调用 IPOPT | 两变量例子解为 `[3,5]`；同一问题与现有 AD 模式一致；闭包参数与多返回值有效 |
| 2. 通用约束 | 线性/非线性约束、Jacobian/Hessian、边界与尺寸校验 | 带活跃约束的问题正确；验证乘子、非单位目标权重、稀疏结构和导数方向 |
| 3. 调用兼容 | 常用选项、结构化结果、错误传播、形状与状态转换 | 旧脚本回归通过；不可行、迭代上限、回调错误等有正确诊断 |
| 4. 基础通用 OPF | 主流程、极坐标多项式成本 AC OPF、完整必要导数 | 同一脚本运行 case9、case30；不手写展开变量；与参考解比较目标和约束残差 |
| 5. OPF 扩展 | 分段线性成本、更多约束/坐标形式、完整乘子回填 | 逐项声明支持范围；覆盖离线设备、重排和相应模型边界 |
| 6. 迁移增强 | 有限差分、迭代回调、更多 MATLAB 语法与库函数 | 只有函数值的程序可求解；索引、形状与参数捕获符合约定 |

阶段 1 的端到端验证应先于大规模接口改造，以确认现有 VM 的可调用对象、回调重入和 GC
生命周期能否直接复用。数值验证包含独立的导数差分检查，但差分检查本身不意味着生产
求解改用差分。

OPF 参考解应注明 MATPOWER 版本、算例、模型选项、求解器与容差。若本机 MATLAB/Octave
无法执行，应记录实际限制和参考结果来源，不能把公式级测试当作整套 OPF 求解通过。

第一阶段的完成标准是“回调式问题经过现有 fmincon 使用 IPOPT 正确求解”；整个基础 OPF
阶段的完成标准是“同一个 runopf 处理不同规模算例并返回验证过的完整结果”。

## 8. 已移植的 OPF 数值函数

`rspower/lib` 中的 OPF 函数以本机 MATPOWER 7.1 为基准，保留 MATPOWER 的函数名、公式、
返回值顺序和注释布局。使用时先加载 `idx_bus.txt`、`idx_gen.txt`、`idx_brch.txt`、
`idx_cost.txt`，再加载函数自身及其依赖。

目前包含：

- `polycost`：多项式成本及其导数；`totcost`：多项式/分段线性成本值；
- `opf_gen_cost_fcn`：多项式发电成本、梯度和 Hessian；
- `opf_power_balance_fcn`：极坐标/直角坐标功率平衡及 Jacobian；
- `dIbr_dV`、`dAbr_dV`、`opf_branch_flow_fcn`：`S`、`P`、`P²`、`I` 四种支路限值及 Jacobian；
- `opf_branch_ang_fcn`、`opf_vlim_fcn`、`opf_veq_fcn`、`opf_vref_fcn`：直角坐标电压约束及一阶导数。

当前这些移植函数未采用 MATLAB 的 struct 与 cell array 接口，`mpc`、`mpopt` 和 `x{:}` 被拆成
显式矩阵参数。电压、功率等向量按 MATPOWER 习惯传入列向量；母线、发电机和支路的列号仍由
`idx_*.txt` 中的 MATPOWER 常量指定。与本项目其他 rspower 函数一致，作为参数传入的行索引
（例如 `ig`、`il`、`idx`、`refs`）使用 0 基索引。

`opf_branch_flow_fcn` 的 `lim_type` 使用数值代替 `mpopt.opf.flow_lim` 字符：

| `lim_type` | MATPOWER 值 | 约束量 |
| ---: | :---: | --- |
| 0 | `S` | 视在功率平方 |
| 1 | `P` | 有功功率 |
| 2 | `2` | 有功功率平方 |
| 3 | `I` | 电流幅值平方 |

回归入口是 `rspower/tests/test_opf_functions.txt`，覆盖两种坐标、四种支路限值、成本和电压约束。
该组函数是 AC-OPF 模型的部分数值内核，不代表完整 OPF 主流程已经实现。现有
`test_opf_fmincon_case30.txt` 是固定展开的 case30 模型，不能替代通用 `runopf`。
功率平衡、支路等约束所需的完整二阶导数仍须补齐。已实现函数保持可用，并在新增的模型
适配层中逐步接入本方案。
